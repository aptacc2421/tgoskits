# Design context — AxVisor Web Console

## Target audience

两类人：

1. **运维/嵌入式工程师** — 在浏览器里长时间盯客户机状态、串口日志、文件传输。
   他们的判断标准是"信息密度是否够、状态是否一眼看清"，不是"好不好看"。
2. **评估采购的技术决策者** — 第一次打开这个界面，30 秒内形成"这产品成不成熟"的印象。
   这一屏决定 AxVisor 是被当成教学项目还是可商用 hypervisor。

## Use cases

- 看：客户机清单、状态、vCPU/内存分配、进入 guest 次数
- 管：启动 / 暂停 / 恢复 / 关闭，查看候选配置池
- 连：网页串口控制台、Shell、文件传输进客户机
- 查：宿主机是什么机器、跑多久、开了哪些能力

## Brand personality

**工业实用风** — 底层系统软件的气质：可靠、精确、不讨好。
参照物是飞机驾驶舱面板和网络设备的管理界面，不是 SaaS 营销页。

- 冷石墨中性色，一个强调色，其余几乎无彩色
- 数字用等宽、对齐、可扫读；文字用工业 grotesk
- 不用渐变、不用玻璃拟态、不用发光、不用卡片套卡片
- 动效只在状态变化时出现，不做装饰动画

## Differentiation（让人记住的那一个点）

**物理核拓扑图**：pCPU 画成一排"插槽"，每个客户机是一条占用带，
悬停任意客户机时它的插槽亮起。这是 hypervisor 独有的信息，
其它产品没有，也是这个界面最值得截图的一屏。

## Constraints

- 数据来自 `/api/manifest` 与 `/api/vms`，导航 100% 由后端 manifest 驱动
- 宿主总内存不由控制面导出，界面如实注明，不编造数字
- 单文件 HTML + CSS + JS，无框架、无构建、离线可开
- 三套主题切换用于方向评审：Industrial（暗）/ Swiss（亮）/ Console（深灰绿）
